Did the agent fix the bug — or just delete the test?

When you tell a coding agent "make the tests pass", the honest path is to fix the code. The lazy path is to weaken the test: delete an assertion, add @skip, edit the expected value, or special-case the exact inputs the test checks. rigged reads a patch's diff and tells you which one it is — before you merge it.

Eight ways to pass a test without fixing anything.

Every one of these makes a red test turn green while the underlying bug remains. rigged separates the diff's test-file changes from its source changes and scores each pattern, weighting the unambiguous tells (a deleted test, a harness check, assert True) far above the merely suspicious.

Under the hood

Diff parser → effect split → weighted signals.

No model, no training. Deterministic, explainable, and fast enough to run on every patch in CI or in an agent's own self-check loop.

01

Parse the diff

A tolerant unified-diff parser recovers per-file hunks and every added/removed line.

02

Split test vs source

Each file is typed as test / source / config. Weakening a test counts very differently from fixing code.

03

Score the tells

Weighted pattern detectors: deleted assertions, skips, expected-value edits, harness detection, input hardcoding, framework subversion — each citing the exact line.

04

Verdict + reasons

Scores sum to clean / suspicious / gaming, with a plain-English reason per signal and the line it fired on.

gate a merge or an agent's self-check
# fail CI (or reject the agent's own patch) when it games the tests
from rigged import analyze

v = analyze(patch_diff, problem=task_description)
if v.verdict == "gaming":
    reject(v.summary)                 # "...deletes the test that must pass."
    for s in v.signals:
        print(s.message, "@", s.file, s.lineno)

Ships as a library, a CLI (git diff | rigged -, exit code = severity), and reads patches from stdin so it drops into a pre-merge hook.

rigged Source & benchmarks Built by Rishikesh Nair · MIT licensed

rigged is a heuristic static detector, not a proof of intent. A flag means a patch exhibits patterns associated with test-gaming; some are legitimate (a spec genuinely changed, a test was correctly removed). It is tuned for high precision so that a flag is worth a human's time, and anything short of a clear tell is surfaced as "suspicious" rather than blocked. The live demo runs the exact published detector in your browser via Pyodide; all benchmark figures are reproducible from the repo. Corpus examples are drawn from the public nebius/SWE-agent-trajectories and princeton-nlp/SWE-bench_Verified datasets.
